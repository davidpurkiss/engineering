# AGENTS.md

Instructions for any coding agent working **inside this repository**.
(If you want to *use* the KB in another project, install the plugin — see the README.)

## What this repo is

A knowledge base of engineering principles, patterns, practices, RFCs and decisions. The
content is markdown with a strict YAML frontmatter header. Structure is by entry type;
domain and stack are tags.

## Ground rules

1. **Never hand-edit anything in `index/`.** It is generated by `scripts/build-index.mjs`.
   Run `npm run index` instead.
2. **Never invent content in the author's voice.** This is a personal, opinionated KB. If
   you're drafting an entry, mark it `status: draft` and flag the parts you inferred rather
   than were told. Ask before asserting an opinion the author hasn't expressed.
3. **One idea per entry.** If a new entry needs two summaries, it's two entries.
4. **Every entry states when it does not apply.** No exceptions.
5. **Run `npm run validate` before declaring a change done.** It is fast and zero-dependency.
6. **Frontmatter `id` must equal `<type>.<filename-without-.md>`.** Validation enforces it.
7. **`kb/decisions/` is append-only.** To change a decision, add a new ADR that
   `supersedes` the old one and set the old one to `status: superseded`.

## Adding an entry

```bash
cp kb/patterns/_TEMPLATE.md kb/patterns/my-thing.md
# edit frontmatter + body, keep the template headings
npm run validate
npm run index
```

Read `docs/frontmatter.md` for the field reference and the controlled vocabularies, and
`docs/taxonomy.md` for how to choose a type.

## Retrieval, for agents assembling context

Prefer loading the smallest useful set:

1. Read `index/INDEX.md` — one line per entry (id, title, status, summary).
2. Match the task against `summary` and `applies_when`.
3. Load only the matching entry files.
4. Follow `related` ids only when the entry itself says the link matters.

Do not read the whole `kb/` tree into context. That is the failure mode this structure
exists to prevent.
